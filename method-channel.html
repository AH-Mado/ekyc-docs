Mobile native integration

For native iOS / Android apps that run DIDC as a Flutter module. DIDC reports its outcomes across the platform boundary as method calls on a channel named h.didc.

Your native host registers a handler for that channel and reacts to the method names below. This is the default transport.

1

When to use it

DIDC signals your app through one of three transports. Pick the one that matches the kind of app embedding it:

00 Host integrationConfigure, embed, and choose a transport — start here → 01 Flutter integrationA Flutter app embedding the DIDC widget → 02 Mobile native integrationA native iOS / Android app running DIDC as a Flutter module You are here 03 Front-end integrationA web page embedding DIDC in an iframe over postMessage →
2

Setup

The method channel is selected automatically, so no explicit call is required. To be explicit on the DIDC side:

Dart 
DIDC.instance.setCommunication(DIDCCommunicationType.methodChannel, metaData);

On the native side, register a handler on the h.didc channel (see §4). For the full configuration surface — every setter DIDC needs before it boots — see the Host integration guide.

3

The h.didc channel

DIDC maps each outcome onto the h.didc channel:

OutcomeChannel methodArgument
Unauthorizedh.unauthorized—
Contract statush.didc.status"signed" | "notEligible"
Continue manuallyh.didc.continueManual—
info
Two outcomes don't arrive on h.didc

Exit — when the flow finishes or the user leaves, DIDC dismisses its own Flutter view. You observe the view going away rather than receiving a method call.

Analytics — analytics events are delivered over your existing event channel, not h.didc. Handle them through your standard analytics integration.

4

Host-side handler

Switch on the method name and react to each outcome:

Kotlin · Android 
MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "h.didc")
  .setMethodCallHandler { call, result ->
    when (call.method) {
      "h.unauthorized"        -> { /* session expired — re-auth, tear down DIDC */ }
      "h.didc.status"         -> { /* call.arguments == "signed" | "notEligible" */ }
      "h.didc.continueManual" -> { /* route the user to your manual flow */ }
      else                    -> result.notImplemented()
    }
    result.success(null)
  }
Swift · iOS 
let channel = FlutterMethodChannel(name: "h.didc", binaryMessenger: messenger)
channel.setMethodCallHandler { call, result in
  switch call.method {
  case "h.unauthorized":        break // session expired — re-auth, tear down DIDC
  case "h.didc.status":         break // call.arguments as? String == "signed" | "notEligible"
  case "h.didc.continueManual": break // route the user to your manual flow
  default:                      result(FlutterMethodNotImplemented)
  }
  result(nil)
}

Remember: exit arrives as the Flutter view dismissing itself, not as a method call — observe the view lifecycle to clean up.
